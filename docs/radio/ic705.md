# IC-705 Dry-Run Hardware Profile

chattybara can now model an IC-705 station setup without opening audio devices,
serial ports, or keying a transmitter.

```sh
cargo run -p chattybara-cli -- rig ic705 profile --out out/ic705.toml
cargo run -p chattybara-cli -- rig ic705 validate out/ic705.toml
cargo run -p chattybara-cli -- rig ic705 civ --operation read-frequency
cargo run -p chattybara-cli -- rig ic705 civ --operation ptt-rx
cargo run -p chattybara-cli -- audio devices --sample-rate 48000 --channels 1
cargo run -p chattybara-cli -- rig ic705 civ-serial --operation read-frequency --port /dev/cu.usbserial-IC705
```

The generated TOML profile has three sections:

- `audio`: host input/output device names, sample rate, channels, and conservative RX/TX gains.
- `control`: CI-V serial port name, baud-rate setting, radio address, controller address, echo setting, and PTT method.
- `safety`: transmit lockout defaults. `allow_transmit` is false in the template.

The `civ` subcommand builds offline CI-V frames for `read-frequency`,
`read-mode`, `ptt-rx`, and `ptt-tx`. It prints JSON and marks `ptt-tx` with
`transmit_risk: true`; it does not send anything to a serial port.

The `civ-serial` subcommand is also dry-run by default. It returns the exact
frame and serial settings that would be used, but does not open a port unless
`--live` is passed. Live transmit-risk operations such as `ptt-tx` additionally
require `--allow-transmit`; without that flag, chattybara fails before opening
the port.

```sh
cargo run -p chattybara-cli -- rig ic705 civ-serial --operation read-frequency --port /dev/cu.usbserial-IC705
cargo run -p chattybara-cli -- rig ic705 civ-serial --operation read-frequency --port /dev/cu.usbserial-IC705 --live
cargo run -p chattybara-cli -- rig ic705 civ-serial --operation ptt-tx --port /dev/cu.usbserial-IC705 --live --allow-transmit
```

Useful IC-705 facts for this scaffold:

- The CI-V reference guide documents USB CI-V remote control and the frame shape.
- The IC-705 default transceiver address used in the guide is `A4`; the
  controller address shown is `E0`.
- With the Icom USB driver installed, the two serial ports are named
  `IC-705 Serial Port A (CI-V)` and `IC-705 Serial Port B`.

Before live rig control, keep hardware experiments behind the explicit
operator opt-ins, verify audio levels into a dummy load or non-radiating test
path, and confirm the station call/signoff workflow outside the code.
